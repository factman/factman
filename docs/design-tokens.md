# Design tokens and the Factman Design System

The site's look comes only from the [Factman Design System](https://claude.ai/artifact/BKe8bcinFg9dC6H9ChDRBm) (PRD section 6). Everything under `src/styles/factman/` is vendored or generated: Prettier and stylelint skip it, and nobody edits it by hand.

| File                       | What it is                                                                                                                                                                           | Loaded                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| `tokens.json`              | The design system's tokens, copied as is                                                                                                                                             | Source only                              |
| `tokens.css`               | Generated by `pnpm ds:tokens`: every token as a custom property, Light on `:root`, Dark on `[data-theme="dark"]`. The unused `legacy-*` palette is left out. 15.8 kB, 3.5 kB gzipped | **Globally**                             |
| `bundle.css`               | The design system's `components/bundle.css` (all `fm-*` classes, 160 kB), copied as is                                                                                               | Source only                              |
| `global.css`               | Split from `bundle.css` by `pnpm ds:split`: what every page needs: `.fm-backdrop`, `.fm-icon`, the shared tone, glass and arrow helpers. 2.8 kB                                      | **Globally**                             |
| `components/<section>.css` | Split from `bundle.css` by `pnpm ds:split`: one file per component section (`button.css`, `tag.css`, `portfolio-sections.css` …)                                                     | **Only with the component that uses it** |

`angular.json` loads `tokens.css`, `global.css`, then `src/styles.scss`.

## Loading component styles per component

The design system ships every component's CSS in one 160 kB bundle. Loading it globally would make every page download styles for about 50 components it never renders (calendar, chat, table, tree …). So component CSS is not global. Each Angular component that ports a design-system component adds that section to its own styles:

```scss
// button.scss
@use 'factman/components/button'; // resolved through stylePreprocessorOptions.includePaths: ["src/styles"]

// component-specific additions below, tokens only
```

```ts
@Component({
  selector: 'fm-button',
  styleUrl: './button.scss',
  // fm-* classes are the shared contract (PRD §6), so they are not scoped per component:
  encapsulation: ViewEncapsulation.None,
  …
})
```

Angular compiles a component's styles into that component, inside the JS chunk of the route that uses it, and adds them to the page only when the component renders. A prerendered page inlines only the styles of the components on it. Nothing is merged back into one global file. This was verified on a build (PR #26): a test component's `tag` section appeared only in its route chunk and that page's HTML, never in the global stylesheet, which dropped from 160.5 kB to 16.9 kB.

`ViewEncapsulation.None` keeps the design system's selectors working as written (for example `.fm-card .fm-btn`, tones), and the CSS still only loads with the component. If two components need the same section, both `@use` it; Sass emits it once per component, which is fine at section size.

**Known design system quirk:** `bundle.css` defines `@keyframes fm-pulse` twice: Skeleton (opacity pulse) and the availability dot (ring pulse, in `portfolio-sections.css`). With per-component loading they only clash on a page that renders both, where the one loaded last wins. Rename one when porting (ETE-70 or the hero work).

## Token layers

1. **Primitives:** raw values: `neutral-*`, `blue-*`, `red-*`, `green-*`, `amber-*`, `ice-*`, `alpha-*` (and the `legacy-*` palette kept for old frames). **Never used directly.**
2. **Semantic tokens:** what components use. Each points at a primitive and carries a Light and a Dark value:
   - ground: `bg-canvas`, `bg-surface`, `bg-sunken`, `bg-inverse` …
   - glass: `glass-fill*`, `glass-panel`, `glass-stroke*`, `glass-chrome*`, `glass-popover`
   - text, icon and border: `text-primary` … `text-tertiary`, `icon-*`, `border-*`, plus status (`danger`, `success`, `warning`, `info`)
   - data: `chart-series-1` … `chart-series-8`
3. **Component and portfolio tokens:** values for one family of components:
   - code editor: `code-*`, `syntax-*`
   - terminal (always dark): `terminal-*`
   - window chrome: `window-dot-*`
   - portfolio accents: `accent-glow`, `status-available`
   - tables and loading: `table-*`, `skeleton-*`
4. **Scales:** spacing (`gap-*`, `padding-*` on a 4px rhythm), `radius-*`, `border-width-*`, `shadow-*` (Light and Dark), `blur-*`, `opacity-*`, layout (`breakpoint-*`, `content-max`, `navbar-height`), motion (`duration-*`, `ease-*`) and fonts (`font-sans`, `font-logo`, `font-mono`).

Dark mode: set `data-theme="dark"` on `<html>` (theme handling is ETE-24). Wrap pages in `.fm-backdrop` for the canvas glow that makes glass read.

## Rules for component styles

`pnpm lint:styles` (stylelint, also part of `pnpm lint` and the pre-commit hook) rejects:

- hex colours, named colours and `rgb()`, `hsl()` …: use `var(--text-primary)`, `var(--glass-fill)` …
- raw values for colour, background, font-size, font-family, border-radius, box-shadow, gap, padding, margin and transition and animation durations: use `var(--gap-md)`, `var(--radius-lg)`, `var(--shadow-glass-regular)`, `var(--duration-fast)` …

Allowed without tokens: `0`, `auto`, `inherit`, `initial`, `unset`, `none`, `transparent`, `currentColor`.

## Updating from the design system

1. Copy the design system's `project/tokens.json` over `src/styles/factman/tokens.json`, and `project/components/bundle.css` over `src/styles/factman/bundle.css`.
2. Run `pnpm ds:tokens` and `pnpm ds:split`.
3. `pnpm test:scripts` fails if the generated files drift from their sources, or if the split loses a line.

## Fonts

Plus Jakarta Sans (body), JetBrains Mono (code, terminal, eyebrows) and Jost (logo wordmarks only) are **self-hosted**. Nothing is loaded from Google, so no request leaves the site before consent (SEC-02).

- `pnpm ds:fonts` copies the Latin and Latin-Extended `woff2` files from the pinned `@fontsource` packages (OFL-1.1) into `src/assets/fonts/`, with the package version in the file name. Vercel caches them as immutable.
- It writes `src/styles/generated/fonts.css`, loaded right after `tokens.css`:
  - `@font-face` rules with `font-display: swap` and a `unicode-range` per subset, so a page downloads only the subsets its text needs
  - size-adjusted local fallbacks (`Plus Jakarta Sans Fallback` on Arial, `JetBrains Mono Fallback` on Courier New, `Jost Fallback` on Arial), computed from Capsize metrics to limit layout shift while fonts load
  - the `--font-sans`, `--font-mono` and `--font-logo` tokens with those fallbacks inserted
- Only the critical file is preloaded: Plus Jakarta Sans Latin, via a `<link rel="preload">` that the script maintains in `src/index.html`.
- Fonts load on use: Jost is fetched only on pages that render a logo wordmark, and JetBrains Mono only where code or mono text appears.
- `pnpm test:scripts` and `pnpm ds:fonts --check` fail if the files, CSS or preload drift from the packages. `e2e/fonts.spec.ts` checks that no request goes to `fonts.googleapis.com` or `fonts.gstatic.com`, and that fonts come from `/assets/fonts/`.

To update the fonts: bump the `@fontsource` package versions, then run `pnpm ds:fonts`.

## Brand assets (logo, favicons)

The AY mark and the ODUNAYO lockup come from the design system's `assets/Logos` artwork. **The mark is never redrawn, recoloured or cropped:** everything the site serves is a resize of those files.

- `src/styles/factman/logos/` holds the originals, copied as is: `factman-mark-light.png` and `factman-mark-dark.png` (1024 × 1024) and `odunayo-lockup-light.png` and `odunayo-lockup-dark.png` (2512 × 768). They are not deployed.
- `pnpm ds:brand` resizes them with `sharp`:
  - `src/assets/brand/`: `ay-mark-{light,dark}-{128,256}.webp` and `odunayo-lockup-{light,dark}-{96,192}.webp` (1x and 2x)
  - `public/`: `favicon.ico` (16, 32, 48), `apple-touch-icon.png` (180, on the light canvas colour because iOS fills transparent corners with black), `icon-192.png`, `icon-512.png`, the maskable `icon-maskable-192.png` and `icon-maskable-512.png` (the mark at 56% of the icon on the light canvas colour, so Android's circle, squircle or rounded-square masks never cut into it; the safe zone is a centred circle of radius 40%) and `site.webmanifest`
- `src/index.html` links the icons, the manifest and `theme-color` (`--blue-900`).
- `pnpm test:scripts` fails if an original no longer matches the design system file (sha256) or an output is missing or the wrong size.

Use the `fm-logo` atom (`@ui/atoms`), never an `<img>` of the artwork:

```html
<fm-logo />
<!-- ODUNAYO lockup, light, 48px mark -->
<fm-logo type="mark" theme="dark" [size]="36" />
<fm-logo [artwork]="true" />
<!-- lockup from its artwork (no Jost needed) -->
```

`theme="light"` artwork (navy bezel and wordmark) goes on light grounds and `theme="dark"` (silver bezel, near-white wordmark) on dark grounds. The live wordmark uses `--font-logo` (Jost), so Jost loads only on pages that render a lockup.

To update: copy the new design system PNGs over the originals, update the hashes in `scripts/design-system/build-brand.ts`, then run `pnpm ds:brand`.
